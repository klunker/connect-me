# ConnectMe: Схема данных Firestore

## Коллекции и структуры документов

### 1. `users/{userId}`
Документ профиля зарегистрированного пользователя. ID документа = `auth.uid`.
> **Приватность:** Документ содержит персональные данные (телефон, email, pushToken). Доступен на чтение и запись **только владельцу** (`request.auth.uid == userId`). Для публичного отображения имени автора (`creatorName`) или участника данные денормализуются прямо в событие и в список участников.

| Поле | Тип | Обязательное | Описание / Ограничения |
|---|---|---|---|
| `displayName` | `string` | Да | Отображаемое имя (1..60 симв.) |
| `email` | `string` | Нет | Email (валидный email формат) |
| `phone` | `string` | Нет | Номер телефона (5..25 симв.) |
| `pushToken` | `string` | Нет | Expo Push Token для пушей (до 255 симв.) |
| `reliabilityScore` | `number` | Нет | Рейтинг надежности (от 0.0 до 1.0, например 0.85 = 85%) |
| `createdAt` | `timestamp` | Да | Время создания аккаунта (неизменяемое) |
| `updatedAt` | `timestamp` | Нет | Время последнего обновления профиля |

---

### 2. `events/{eventId}`
Основной документ события. ID документа = автогенерируемый ID (или уникальная строка).
> **Доступ:** Публичное чтение (`allow read: if true`), чтобы гости по ссылке на GitHub Pages могли видеть детали без обязательного предварительного логина. Создание — только зарегистрированные пользователи. Изменение/управление — создатель (`creatorId`) или назначенный делегат (`delegatedTo`). Удаление — только `creatorId`.

| Поле | Тип | Обязательное | Описание / Ограничения |
|---|---|---|---|
| `title` | `string` | Да | Название события (1..100 симв., напр. «Баскетбол 5х5») |
| `description` | `string` | Нет | Описание, правила, детали (до 1000 симв.) |
| `location` | `string` | Да | Место проведения (1..200 симв., адрес или название площадки) |
| `dateTime` | `timestamp` | Да | Дата и время проведения сбора |
| `creatorId` | `string` | Да | UID создателя (неизменяемое) |
| `creatorName` | `string` | Да | Имя создателя (1..60 симв., для отображения гостям) |
| `requiredCount` | `number (int)` | Да | Сколько людей нужно (целое число от 1 до 100) |
| `isRecurring` | `boolean` | Да | Циклическое ли событие |
| `recurrenceRule` | `string` | Нет | Правило повторения, напр. `"weekly:thursday"` |
| `parentEventId` | `string` | Нет | Если это экземпляр серии — ссылка на родительский eventId |
| `status` | `string` | Да | Статус: `'open'`, `'confirmed'`, `'cancelled'`, `'past'` |
| `delegatedTo` | `string` | Нет | UID пользователя, которому передано управление (или `null`) |
| `createdAt` | `timestamp` | Да | Время создания (неизменяемое) |
| `updatedAt` | `timestamp` | Нет | Время последнего изменения |

---

### 3. `events/{eventId}/participants/{participantId}`
Подколлекция участников события. ID документа = `request.auth.uid` (для зарегистрированных пользователей или анонимного гостя).
> **Доступ:** Публичное чтение (`allow read: if true`). Добавление/обновление своего статуса — владелец документа (`participantId == request.auth.uid`). Изменение статуса посещаемости (`attended` / `no_show`) — создатель события или делегат.

| Поле | Тип | Обязательное | Описание / Ограничения |
|---|---|---|---|
| `userId` | `string` | Да | UID пользователя (зарегистрированного или анонимного гостя) |
| `displayName` | `string` | Да | Имя участника (1..60 симв.) |
| `status` | `string` | Да | Статус участия: `'going'` (пойду), `'not_going'` (не пойду), `'confirmed'` (подтвердил участие перед игрой), `'attended'` (пришел), `'no_show'` (не явился) |
| `isGuest` | `boolean` | Да | `true` если гость по веб-ссылке, `false` если зарегистрированный |
| `respondedAt` | `timestamp` | Да | Время ответа/обновления статуса |
